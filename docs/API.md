# REST API

Все маршруты ниже имеют префикс /api. Обмен — JSON UTF-8, даты — YYYY-MM-DD. Создание возвращает 201, чтение и изменение — 200, удаление, регистрация и выход — 204.

## Вход и CSRF

1. GET /auth/csrf без входа возвращает token и headerName.
2. POST /auth/login, Content-Type application/x-www-form-urlencoded, поля username и password, заголовок из шага 1. Сохраняйте cookie сессии.
3. После успешного входа повторно запросите /auth/csrf: при аутентификации токен меняется.
4. Для POST, PUT, PATCH, DELETE передавайте новый токен в X-XSRF-TOKEN.
5. POST /auth/logout с токеном завершает сессию.

GET /auth/me возвращает user с полями id, username, fullName, role, а также today. Сервер использует APP_ZONE для даты дневника.

## Примеры тел запросов

Для новых аккаунтов поле username содержит email. Существующие логины продолжают работать.

Самостоятельная регистрация (поле rehabilitationReason необязательно):

    {"username":"ivan@example.test","password":"PatientPassword2026!","passwordConfirmation":"PatientPassword2026!","fullName":"Иван Петров","birthDate":"1995-03-12"}

Создание специалиста:

    {"username":"doctor-new@example.test","password":"DoctorPassword2026!","passwordConfirmation":"DoctorPassword2026!","fullName":"Иван Петров"}

Для этих двух запросов пароль должен иметь от 10 символов, занимать максимум 72 байта UTF-8 и содержать строчную и заглавную буквы, цифру и спецсимвол.

Назначение специалиста: {"specialistId":2}. Чтобы снять назначение, передайте {"specialistId":null}.

Создание пациента сотрудником:

    {"username":"ivan@example.test","password":"PatientPassword2026!","fullName":"Иван Петров","birthDate":"1995-03-12","rehabilitationReason":"После травмы","notes":"","specialistId":2}

Упражнение:

    {"title":"Ходьба","instructions":"Условия определяет специалист","unit":"MINUTES"}

План:

    {"title":"План восстановления","goal":"Вести дневник занятий","startsOn":"2026-11-02","endsOn":"2026-11-30"}

Назначение:

    {"exerciseId":1,"targetAmount":20}

Состояние:

    {"status":"ACTIVE","version":0}

Запись:

    {"assignmentId":1,"performedOn":"2026-11-02","status":"DONE","actualAmount":15,"pain":2,"wellbeing":7,"comment":"Занятие выполнено","version":null}

Для изменения укажите текущую version. Дату и назначение существующей записи менять нельзя. Для SKIPPED нужны actualAmount=0 и непустой комментарий. Для DONE факт строго больше нуля.

Ответ специалиста:

    {"text":"Спасибо за запись","version":0}

После ответа версия записи также увеличивается.

## Состояния и валидация

Допустимы DRAFT → ACTIVE → COMPLETED → ARCHIVED, а также DRAFT → ARCHIVED. Обратных переходов нет. Одновременно у пациента один ACTIVE. Активация требует упражнений и неистёкшего периода. Завершить план до его начала нельзя. Назначения фиксируются при активации.

Период: конец не раньше начала и не дальше чем через 365 дней от начала, то есть до 366 включительных календарных дат. Нагрузка назначения: 0,01–100000. Факт: 0–100000 с дополнительными условиями статуса. Боль: 0–10. Самочувствие: 1–10. Дата занятия не позже серверной даты и внутри периода плана.

## Ошибки

400 — неверное значение/формат; 401 — необходим вход; 403 — нет прав или неверный CSRF; 404 — объект не найден; 409 — дубль, устаревшая версия или запрещённый переход.

Бизнес-ошибки возвращаются как ProblemDetail с полями status, detail, title. Ошибки фильтра безопасности возвращают JSON с detail; клиент опирается на HTTP-статус и это поле.

Поля passwordHash не входят в публичные DTO. В JSON не возвращаются JPA-сущности пациентов и пользователей. Swagger генерируется по контроллерам и не заменяет серверные проверки доступа.

В маршрутах чата id — идентификатор карточки пациента. Канал DOCTOR доступен пациенту и назначенному специалисту, канал SUPPORT — пациенту и администраторам. При смене специалиста начинается отдельный диалог; новый специалист прежнюю переписку не видит. Состояние прочтения в очереди поддержки общее для администраторов. Для отзыва используйте {"text":"…"} (до 1000 символов).
