# Как устроена программа «Точка опоры»

Этот разбор относится к коду в папке java/rehab-diary. Его удобно читать с открытым проектом в IntelliJ IDEA: сначала найдите указанный файл, затем соответствующий класс или метод.

## 1 Что запускается

Это одно Java-приложение с браузерным интерфейсом. Сервер одновременно отдаёт страницы и принимает запросы к данным. Отдельный сервер для фронтенда не нужен.

start.cmd → scripts/start.ps1 → Java → app/rehab-diary.jar → RehabApplication.main().

RehabApplication запускает Spring Boot. Внутри JAR находится встроенный сервер Tomcat, классы Java и статические файлы интерфейса. При запуске из IDE точка входа та же: src/main/java/ru/coursework/rehab/RehabApplication.java.

pom.xml описывает зависимости и сборку. Исходный код находится в src, готовая сборка — в app. Редактирование Java-файла не меняет уже собранный JAR: после изменений нужно выполнить build.cmd или Maven verify.

## 3 Где фронтенд

Все исходники интерфейса находятся в src/main/resources/static.

| Файл | Что делает |
|---|---|
| index.html | Основной HTML-каркас, область приложения, диалог формы и уведомление |
| style.css | Цвета, шрифты, размеры, карточки, таблицы и правила мобильной ширины |
| app.js | Вход, переключение экранов, формы, запросы к API, графики |
| favicon.svg | Значок приложения |

В app.js функция login() показывает форму входа. start() получает текущего пользователя, список доступных пациентов и упражнения. loadPlans() и loadDetail() загружают выбранные планы и дневник. render() строит рабочий экран.

overview() отвечает за обзор, plansPage() — за планы, diary() — за дневник, progressPage() — за графики. patientsPage() и exercisesPage() нужны сотрудникам. auditPage() показывает журнал администратору.

Формы создаются функциями planForm(), assignmentForm(), entryForm(), feedbackForm(), patientForm(), exerciseForm(). Общая modal() выводит форму и сохраняет её после успешного запроса.

Функция api(path, method, body) выполняет fetch. Она добавляет префикс /api, превращает объект в JSON, передаёт CSRF-токен и обрабатывает HTTP-ошибки. esc() экранирует пользовательский текст перед вставкой в HTML.

chart() строит SVG-график. По горизонтали учитываются фактические календарные интервалы между датами. Для боли и самочувствия верхняя граница оси равна 10. Разные упражнения и единицы нагрузки не складываются в одну кривую.

Объект state в JavaScript — временное состояние экрана: выбранный пациент, выбранный план и загруженные ответы. После обновления страницы эти сведения загружаются заново. Постоянные записи хранятся в серверной базе.

## 4 Где API

Основной файл — src/main/java/ru/coursework/rehab/api/ApiController.java.

Аннотация @RestController указывает, что методы обрабатывают HTTP-запросы и возвращают данные. @RequestMapping("/api") задаёт общий префикс. Например, @PostMapping("/entries") вместе с ним образует POST /api/entries.

| Запрос | Метод контроллера | Вызов бизнес-логики |
|---|---|---|
| GET /api/patients | patients() | service.patients() |
| POST /api/patients | patient(input) | service.createPatient(input) |
| GET /api/patients/{id}/plans | plans(id) | service.plans(id) |
| POST /api/patients/{id}/plans | plan(id,input) | service.createPlan(id,input) |
| GET /api/plans/{id} | detail(id) | service.detail(id) |
| POST /api/plans/{id}/assignments | assignment(id,input) | service.addAssignment(id,input) |
| PATCH /api/plans/{id}/status | status(id,input) | service.changeStatus(id,input) |
| POST /api/entries | entry(input) | service.writeEntry(null,input) |
| PUT /api/entries/{id} | edit(id,input) | service.writeEntry(id,input) |
| PUT /api/entries/{id}/feedback | feedback(id,input) | service.feedback(id,input) |
| GET /api/plans/{id}/progress | progress(id) | service.progress(id) |
| GET /api/plans/{id}/export | csv(id) | service.csv(id) |
| GET /api/audit | audit(page) | service.audit(page) |

Полный перечень, включая упражнения, специалистов и аутентификацию, приведён в docs/API.md. Актуальный машинный контракт — /v3/api-docs работающего сервера; интерфейс его просмотра — /swagger-ui.html.

Вход и выход — особый случай: POST /api/auth/login и POST /api/auth/logout обрабатываются фильтрами Spring Security из SecurityConfig, а не обычным методом ApiController. Контроллер выдаёт CSRF-токен и данные текущего пользователя.

Requests.java содержит входные DTO: PatientInput, PlanInput, AssignmentInput, EntryInput и другие. @NotBlank, @NotNull, @Min, @Max и похожие аннотации проверяют форму входных данных.

Views.java содержит выходные DTO: UserView, PatientView, PlanView, AssignmentView, EntryView, PlanDetail. DTO — это объект передачи данных. В ответе пользователь получает нужные поля; passwordHash не входит в UserView.

ApiExceptionHandler.java переводит ожидаемые ошибки в HTTP-ответы: 400 — некорректные данные, 403 — нет доступа, 404 — не найдено, 409 — конфликт или дубль. Отсутствие входа даёт 401 через фильтр безопасности.

## 5 Где бизнес-логика

Основной файл — service/RehabService.java.

Контроллер знает, какой маршрут вызван, а сервис определяет, разрешено ли действие и как оно меняет программу.

| Метод | Основная ответственность |
|---|---|
| actor(), access(), requireStaff() | Текущий пользователь, роль и доступ к пациенту |
| createPatient() | Аккаунт пациента, уникальность логина, закрепление за специалистом |
| createPlan() | Черновик с корректным периодом |
| addAssignment(), removeAssignment() | Изменение назначений только в черновике |
| changeStatus() | Допустимые переходы, один активный план, проверка версии |
| writeEntry() | Создание и изменение занятия с проверкой владельца, даты, статуса и дубля |
| feedback() | Ответ специалиста к актуальной версии записи |
| progress() | Загрузка данных и вызов ProgressCalculator |
| csv() | Формирование выгрузки и экранирование ячеек |
| audit() | Запись операции в журнал или чтение журнала администратором |

План проходит DRAFT → ACTIVE → COMPLETED → ARCHIVED. Черновик также можно сразу отправить в архив. Это конечный автомат, реализованный enum и проверками условий в changeStatus(). Отдельных классов GoF State в проекте нет.

Пример правила, которого нет в стандартном CRUD: нельзя активировать пустой план или второй активный план пациента. Другой пример: для SKIPPED нагрузка должна быть нулевой, а причина — непустой; для DONE нагрузка должна быть больше нуля.

После активации упражнения фиксируются. Для смены программы создаётся следующий план. Assignment хранит снимок названия, инструкции, единицы и цели, чтобы история не зависела от будущего изменения справочника.

## 6 Где и как хранятся данные

Настройки подключения — src/main/resources/application.yml. По умолчанию используется jdbc:h2:file:./data/rehab;DB_CLOSE_ON_EXIT=FALSE.

H2 — встроенная реляционная база данных. Она работает внутри процесса Java, а на диске сохраняет таблицы в data/rehab.mv.db. Этот бинарный файл нельзя редактировать как текст. Записи пациента, планы и ответы сохраняются в нём между запусками.

| Java-сущность в domain | Таблица | Содержимое |
|---|---|---|
| Account.java | accounts | Логин, хеш пароля, имя, роль |
| Patient.java | patients | Карточка пациента, его аккаунт и специалист |
| Exercise.java | exercises | Справочник упражнений и единицы |
| RehabPlan.java | rehab_plans | Цель, период, состояние, версия плана |
| Assignment.java | assignments | Упражнение, назначенное в план, снимок условий |
| DiaryEntry.java | diary_entries | Дата, статус, факт, боль, самочувствие, комментарий и ответ |
| AuditEvent.java | audit_events | Кто, когда и какой объект изменил |

@Entity обозначает класс сущности, @Table — таблицу, @Id — первичный ключ. @ManyToOne и @OneToOne задают связи. Hibernate преобразует Java-объекты в SQL-операции и восстанавливает объекты из строк таблиц.

Интерфейсы repository/ наследуют JpaRepository. Например, EntryRepository работает с DiaryEntry. Методы вроде findByAssignmentPlanIdOrderByPerformedOnDescIdDesc() описывают выборку: записи назначений определённого плана по убыванию даты и id. Реализацию интерфейса создаёт Spring Data.

В БД есть ограничения уникальности: логин; аккаунт карточки пациента; пара «план, упражнение»; пара «назначение, дата». Сервис предварительно проверяет конфликт, а БД дополнительно защищает данные.

DemoData.java — начальная загрузка. В пустую базу добавляются учебные аккаунты и справочник; при DEMO_DATA=true также добавляются вымышленные пациенты, план и дневник. Если аккаунты уже существуют, повторный запуск не сбрасывает базу.

При изменении DB_URL можно указать другую базу; драйвер PostgreSQL включён. Текущая проверенная конфигурация — файловая H2. Тесты используют отдельные H2 в памяти и не меняют пользовательский data/rehab.mv.db.

Для резервного копирования остановите сервер, затем скопируйте папку data. Перенос исходников без data создаёт новую базу; перенос вместе с data сохраняет прежние записи. Пароли исходной конфигурации применяются только при первом создании аккаунтов.

## 7 Какие паттерны и подходы используются

### Многослойная архитектура

Цепочка зависимостей: браузер → контроллер → сервис → репозиторий → база. Отдельно существуют сущности, DTO и настройки. Архитектурно это монолит: слои работают внутри одного приложения.

### Service Layer

RehabService определяет операции предметной области. Здесь объединены права, состояние плана, проверки и сохранение. Например, writeEntry() — операция «записать занятие», а не просто вызов save().

### Repository

JPA-репозитории скрывают стандартный доступ к хранилищу за интерфейсами. Бизнес-логике не нужно вручную открывать JDBC-соединение и писать INSERT для каждой операции.

### DTO

Requests и Views отделяют формат HTTP от структуры таблиц. Один PlanDetail может объединять план, назначения и дневник. Одновременно сущность Account с хешем пароля не отправляется целиком в браузер.

### Dependency Injection

Зависимости передаются через конструкторы. Spring создаёт RehabService, репозитории, PasswordEncoder и Clock и связывает их. В ApiController не создаётся new RehabService(...); контроллер получает готовый сервис.

### ORM и отображение объектов

Hibernate отвечает за отображение сущностей и связей в реляционные таблицы. Это подход ORM, близкий к Data Mapper. Настройки JPA и аннотации определяют отображение.

### Транзакционная граница и блокировки

@Transactional объединяет связанные изменения. Если при записи занятия возникает исключение, изменения и событие аудита откатываются вместе.

Пессимистическая блокировка строки Patient согласует параллельную активацию, запись занятия и завершение плана. @Version в плане и записи обеспечивает оптимистическую проверку устаревших данных из формы. Это разные механизмы для разных конфликтов.

### Front Controller на уровне Spring MVC

Фреймворк принимает HTTP-запрос через DispatcherServlet и направляет его методу контроллера. Приложение предоставляет JSON, а представление строит браузер. Поэтому здесь разделение модели, представления и управления, но нет серверных HTML-шаблонов Thymeleaf.

Называть любые if-условия «Стратегией» или «Состоянием» в смысле GoF было бы неточно. Отдельных Strategy, Observer и фабрик предметных объектов в этом коде нет. Spring-bean по умолчанию имеет singleton scope, но это не самописный Singleton с getInstance().

HTTP API следует ресурсному стилю, но аутентификация использует серверную сессию JSESSIONID. Поэтому полностью stateless REST в строгом смысле не реализован.

## 8 Путь одной записи от кнопки до диска

1. Пациент нажимает «Записать занятие». entryForm() показывает поля.
2. После подтверждения api('/entries','POST',body) отправляет POST /api/entries.
3. Spring Security проверяет сессию и CSRF-заголовок.
4. ApiController.entry() получает EntryInput; @Valid запускает структурную валидацию.
5. Контроллер вызывает RehabService.writeEntry(null,input).
6. Сервис получает назначение и пациента, проверяет владельца, блокирует пациента, перечитывает план.
7. Проверяются активное состояние, дата, фактическая нагрузка, причина пропуска и отсутствие дубля.
8. EntryRepository.saveAndFlush() сохраняет DiaryEntry через Hibernate в H2.
9. В той же транзакции сохраняется AuditEvent.
10. Views.EntryView.of() формирует ответ без служебных данных.
11. Клиент получает HTTP 201 и перечитывает дневник и прогресс.
12. render() обновляет таблицу, показатели и графики.

При ошибке сервер возвращает код и detail. Форма остаётся открытой. Клиентская проверка удобна пользователю, но обход формы прямым запросом не отменяет серверные проверки.

## 9 Как считается прогресс

service/ProgressCalculator.java — отдельный класс без HTTP и БД. Он получает план, назначения, записи и сегодняшнюю дату.

Число ожидаемых занятий = количество упражнений × число прошедших дней плана, включая сегодня. Будущие дни не учитываются. Досрочное завершение фиксирует последнюю учитываемую дату.

Регулярность = выполненные занятия / ожидаемые × 100%. Достижение цели считается отдельно: фактическая нагрузка не ниже назначенной. Поэтому выполнение части нагрузки считается занятием, но не достижением целевого объёма.

Явный пропуск отличается от отсутствия записи. Пропуски не включаются в график физической нагрузки как нулевые измерения. Все показатели описывают выполнение плана и дневник, а не процент выздоровления.

## 10 Что менять для конкретной задачи

| Изменить механизм входа | config/SecurityConfig.java и клиент login()/api() |

## 11 Как объяснить на защите

«Программа построена по многослойной архитектуре. Фронтенд — HTML, CSS и JavaScript в static. API находится в ApiController. Контроллер принимает DTO и вызывает RehabService. Сервис проверяет права, состояние плана и правила дневника. Репозитории Spring Data JPA сохраняют сущности через Hibernate в файловую H2. Отдельный ProgressCalculator считает показатели. Основные подходы — Service Layer, Repository, DTO, Dependency Injection и транзакции».

Далее откройте в IDE ApiController.entry(), RehabService.writeEntry(), EntryRepository и DiaryEntry. Так можно показать объяснение непосредственно на коде.
